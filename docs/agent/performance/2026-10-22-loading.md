# Loading optimization measurements — 2026-10-22

Compared production builds of the working tree immediately before this change and after it. Both served by Vite preview on the same Windows host with the same `/backend` proxy to the real test API. Desktop Chromium/in-app browser emulating a 393×852 viewport; no CPU/network throttling; browser cache disabled; three independent navigations per measurement, medians below. This is a local development-machine comparison, not a claim about mobile hardware or public-network performance.

| Measurement | Before | After |
| --- | ---: | ---: |
| Primary panel DOM ready | 391.9 ms | 101.8 ms |
| Building cards DOM ready | 834.7 ms | 474.0 ms |
| Campus map DOM ready (map exists, loading mask removed) | 567.0 ms | 581.9 ms |
| GUK floor canvas after click | 690.3 ms | 551.0 ms |
| Initial route JS, uncompressed | 565,357 bytes | 525,398 bytes |
| Same JS files, gzip estimate | 180,551 bytes | 169,428 bytes |

The map result is effectively unchanged/slightly slower in this sample; external Yandex/API timing varies. Panel/card improvements primarily come from resolving initial translations before mounting the app-wide Suspense boundary, eliminating its startup fallback delay. These are DOM milestones, not Lighthouse/FCP/LCP scores. CSS, fonts, photographs, and third-party Yandex files are not included in the JS-byte row. Gzip is computed per emitted file locally; preview is not assumed to serve compressed responses.

Transition test begins from a fresh home document and sends a pointer-intent event 120ms before clicking GUK in both builds. After can overlap destination code/floor fetching during that interval. No entire-campus/whole-floor prefetch is performed at startup; save-data disables intent prefetch. Baseline/after canvases are observed with the same temporary MutationObserver probe injected only into benchmark HTML, never source. Probes were removed after measurement.

## Implementation

- Settings dialog code loads on first opening, keeps its loaded instance for exit animations, and shows a loading/close fallback while fetching. Results and Route body have separate lazy chunks with existing skeleton fallbacks.
- First two building photos remain eager; others get a source only when intersecting the visible carousel (respecting clipping). At settled 393px home, 4 of 6 photos are requested; the last two load upon horizontal scrolling. Fixed photo slots and async decoding avoid layout changes.
- Golos UI font is preloaded. Main interface mounts after the initial locale promise resolves; map and building API continue independently.
- Initial locale comes from explicit `urfuNavigator.language`, then the browser's ordered navigator.languages, then Russian. `en-US→en`, `zh-CN→zh`, `ar-SA→ar`, `de-DE→ru`, and `de-DE,en-US→en` were verified. Manual Russian persisted after reload with English/German browser preferences. Legacy auto-detection cache does not override browser preferences. Local JSON files are served from `/locales/<base-language>/translation.json`; html lang is updated. Full Arabic layout mirroring is outside this change.

## Validation

FSD/ESLint and TypeScript production build pass. Browser checks covered manual/automatic language choice, settings lazy loading, carousel deferred images and scrolling, destination prefetch, and search result lazy loading. Raw timing samples and size summary are saved alongside this report in `docs/agent/performance/`.
