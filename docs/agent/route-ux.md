# UX маршрута — требует доработки

Дата: 2026-10-24. Статус: функциональность реализована частично, UX не завершён и требует отдельной доработки и проверки на реальных телефонах. Прохождение автоматических тестов не означает приёмку мобильного сценария.

## Текущее поведение

- Редактор маршрута открывается отдельной панелью; обычная панель скрывается и становится inert. В редакторе нет отдельной кнопки «Назад»; мобильный возврат обрабатывается историей панелей, на десктопе есть крестик.
- Два поля по 40px, промежуток 6px, без SVG-точек. Крестик виден только при содержимом поля. Пустой редактор ограничен заголовком, без истории; активация поля раскрывает поиск.
- На странице корпуса пустое «Откуда» заполняется явным входом первого этажа из API: главный вход приоритетен, иначе стабильный выбор по ID. На главной без корпуса такой подстановки нет. Ручная точка не перезаписывается, устаревшие ответы отбрасываются по revision и destinationId.
- После заполнения «Откуда», если «Куда» ещё не выбрано, открывается его редактирование с autoFocus. Фактическое открытие экранной клавиатуры после асинхронного ответа зависит от браузера.
- История отмечена иконкой часов; при выбранном «Откуда» заполняет «Куда», иначе «Откуда». Текстовые результаты заполняют активное поле. Категории из этого сценария исключены.
- Когда выбраны обе точки и поиск завершён, маршрут заменяет содержимое основной панели. В сложенном виде видны оба поля, минимальная мобильная высота 126px; история скрыта. Для сброса построенного маршрута сохранена отдельная кнопка в компактной панели.
- После смен этажей системный Back один раз возвращает непосредственно предыдущий этаж; следующий Back выходит из маршрута. Более ранняя цепочка этажей не перебирается. Вложенные поиск/карточки/настройки имеют собственные состояния возврата.

## Что ещё доработать и проверить

1. Согласовать полную модель состояний: пустой редактор, одна точка, активное редактирование, готовый маршрут, очистка одной/обеих точек, повторный вход и выход. Проверить, не возникают ли промежуточные размеры и лишние открытия панели.
2. Проверить Android Back с открытой/закрытой клавиатурой, последовательность «смена этажей → один возврат → выход из маршрута», ручное закрытие и переход между корпусами. Недавние сообщения пользователя о сворачивании браузера требуют проверки на устройстве после исправлений.
3. Проверить фактический курсор и экранную клавиатуру после входа из API, выбора «Отсюда», истории и ручного поиска; разрешить явное повторное редактирование начала без перехвата фокуса.
4. Проверить понятность подстановки входа и выбора входа при нескольких точках Exit; при отсутствии входа оставить ручной выбор, не придумывать координаты.
5. Проверить поведение истории в обоих полях, особенно когда начало заполнено, но пользователь намеренно его редактирует. Текущее правило назначения истории отражает последнее требование, но нуждается в UX-проверке.
6. Проверить мобильную высоту/скролл редактора, клавиатуру, положение кнопок этажей, переход к построенному маршруту и доступность закрытия на всех размерах экрана.
7. Исправить известную проблему текстового поиска: `р-202` / `р 202` дают нерелевантную выдачу, `р202` не находит аудиторию (со слов пользователя; источник web/API пока не установлен). Варианты должны находить одну и ту же аудиторию.
8. Проверить ошибки сети, отсутствие пути, межэтажные и межкорпусные точки, повторный выбор и устаревшие ответы. Не выдавать текущее наличие двух точек за подтверждение успешного построения пути.

## Ответственность и документация

Маршрутный UX, API-запросы, точки, панели, фокус и browser history принадлежат UrfuNavigator-web. konva-floor-plan рисует переданный путь и управляет canvas; она не выбирает входы и не хранит историю панелей. API/admin-данные этими UI-правилами не переписываются.

Основные файлы: src/app/model/useRoutePresentation.ts, src/app/model/usePanelBack.ts, src/app/lib/panelHistory.ts, src/entities/route/model/routeSlice.ts, src/features/point-search/model/fillRouteEntrance.ts, src/features/point-search/ui/RouteSearchField.tsx, src/widgets/side-menu/ui/RouteOverlay.tsx, RouteHeader.tsx и RoutePanel.tsx.

Эта запись уточняет исторические записи в changelog: прежние размеры 80px для маршрута, безусловный выбор «Куда» из истории, отдельная стрелка в редакторе и последовательный возврат по всем этажам больше не являются актуальными.
